# 两段式视觉评审（主代理 × 监视器子代理）

依据：`experience.md` §23 —— 训练统计会骗人（0% 成功率掩盖过真实爬楼进展），
画面不会。规程见 `agent.md` §8；工具是 `scripts/frames.py`（设计见 `doc/frames.md`）。

**两段式**：先整段粗切片评整体；只有第一轮写「需要细看」时，才按 25 fps 摊开
0.4~1.0 s 的短窗口再看一遍。不做更细的切片。

## 分工（强制）

| 角色 | 做 | 不做 |
| --- | --- | --- |
| 主代理（你） | 渲染、切片、派发评审、把结论写进台账、定根因 | 不逐帧看图（省上下文） |
| 监视器子代理 | 用 `read_image` 逐帧看图、按 rubric 产出结构化评审 | 只读；不改代码、不写文档、不跑训练 |

监视器用 DSH 的 `subagent` 工具起（fresh context）：**每份评审一个子代理**，
返回给你的只有文本。

## 0. 准备：渲染一段「真 25 fps」的视频

25 fps 来自 `scripts/play.py` 的 `FRAME_STRIDE=2`（50 Hz 控制 → 每 2 步一帧）。
但 `play.video_max_frames=300` 会在长回合上把取帧间隔稀疏到 80 ms（12.5 fps）。
评审渲染用一份**只改 play 段**的配置（不改代码）：

```yaml
# .tmp/review_play.yaml
play:
  episodes_video: 1          # 一次一个回合：粗切片才有帧数留给整段
  episodes_eval: 100
  seed: 0
  video_max_frames: 500      # 20 s 回合也保持 25 fps
  stages: auto
  batch: ""
```

```bat
.venv\Scripts\python.exe scripts\play.py --run <名字> --mode video --stage <级> ^
    --video-scale 1 --config .tmp\review_play.yaml --batch <批次>
```

产物：`runs/<run>/videos/<批次>/<阶段>/<阶段>.mp4`（25 fps、960×540、带 HUD）。
**视觉评审必须 `--video-scale 1`**：默认降采样到 480×270 时 1px≈3 mm，
「某足是否离地」物理上不可判读。

## 1. 粗切片（整段）

```bat
.venv\Scripts\python.exe scripts\frames.py ^
    runs\<run>\videos\<批次>\<阶段>\<阶段>.mp4 ^
    .tmp\review\<run>\<阶段>\coarse --coarse 12
```

- 12 帧 = 首 2 + 均匀中间 + **末 4**（结局必须可见），拼成 **1 张 3×4 拼图**，
  每格烧 `fNNN t=1.24s`；同时留单帧 `f000.png…` 供引用。
- 预算：1 张图 ≈1–1.5k token；粗切片最多 2 张（`--coarse 24`）。

## 2. 第一轮评审：整体效果（派监视器）

Prompt 模板（`{}` 为占位）：

```text
你是机械狗训练视频的视觉评审员。先用 read_image 看整段拼图 {sheet路径}，
再按需看单帧 fNNN.png（read 工具只能读文本，看图必须用 read_image）。
帧时间戳在 {manifest路径}；视频 {mp4路径}；场景：{台阶高 / 平地}；
共 {N} 帧，覆盖全长 {T} 秒。

禁止：修改任何文件；根据代码或训练数字推断结论——只报告画面里看到的东西，
每条结论必须引用帧文件名（如 f007.png）。

按 rubric 评**整体效果**（通过 / 可疑 / 失败 + 帧证据）：
1. 躯干姿态：俯仰/侧倾/机身高度相对台阶面的变化是否平稳。
2. 步态：对角小跑或爬行步是否成形；拖腿、双腿同相、原地踏步。
3. 结局与失败原因：成功 / 摔倒 / 卡住 / 超时；从哪一帧开始出现征兆；
   失败原因按画面归因（如「前足未抬起直接撞立面」「跨级时重心后坐」）。
4. 指令跟踪：画面位移方向与 HUD 指令行是否一致（HUD 在左上角；
   注意「前进/速度」是回合末值，不能用来验证实时位移）。

输出格式（严格）：
## 总评
{阶段名}：通过 / 可疑 / 失败 —— 一句话理由
## 逐项
（rubric 四项，各带帧证据）
## 是否需要细看
是 / 否。若是：给 1–2 个窗口 t=A–B（各 0.4–1.0 s），并说明怀疑哪一项、
为什么 12 帧不够。
## 假设
（不超过 3 条根因假设，标注置信度；明确说明这是假设不是结论）
```

**这一轮不要判接触类毫秒事件**（踩实/滑擦/磕边）：12 帧均匀采样本来就看不见，
强迫它判只会得到「无法判定」。粗切片只回答“整体像不像会走、结局是什么”。

## 3. 判定与细切片（按需）

多数回合到此结束。只有第一轮写「需要细看」或主代理从总评里看出疑点时，才做：

```bat
.venv\Scripts\python.exe scripts\frames.py ^
    <同一个 mp4> .tmp\review\<run>\<阶段>\w1 --window 1.24:1.84
```

- 窗口 0.4~1.0 s，按视频**原生 25 fps**（40 ms/帧）摊开 ⇒ 10~25 帧，拼成
  2 张 3×3 以内；同时留单帧。
- **每回合最多 2 个窗口**；同一回合的两个窗口算一份证据，不是两份。
- 视频若不足 25 fps，工具直接报错并给出重渲命令：**不插帧、不降级**。

## 4. 第二轮评审：只看窗口（新监视器）

- 只给该窗口的帧与 manifest；**不要给第一轮的结论**（避免顺着预期报喜）。
- 问题保持中立：

```text
下面是从训练视频 {A–B} 秒截出的连续帧（25 fps，40 ms/帧）。用 read_image 逐帧看，
描述这段时间里足端与躯干发生了什么：落点在台阶什么位置、踩实还是悬空、
有没有压边/打滑/二次试探、机身有没有异常下沉或抬头。
只报告画面里看得到的；每条结论引用帧号。
输出：## 观察（按时间）## 结论（可疑 / 未见异常 + 一句话）## 假设（≤3 条）
```

每窗口 ≤2 张图。

## 5. 回收与落账（主代理）

- **盲评纪律**：prompt 里不要写「这版应该修好了 X」；第一轮给出的窗口建议只是
  线索，第二轮 prompt 不带结论。
- 结论进 `train.md` 该 run 的「解读」；新根因按 `agent.md` §1 义务 2 写进
  `experience.md`。
- 对照评审（两臂谁好）：两个视频各派一个子代理、用同一段 rubric，主代理汇总；
  **不要让单个子代理连读两份帧序列**。
- 数字/遥测不得替代画面证据（`doc/contact_reward_design.md` §6.2 ③）。

## 预算

粗 1–2 张 + 细每窗 ≤2 张（每回合 ≤2 窗）⇒ 单回合 **≤6 张图**（≈6–9k token）。

## 已知的坑

- `read_image` 只吃 png/jpg/jpeg/webp/gif；**mp4 不能直读**；GIF / 动画 WebP /
  APNG 只会出第一帧（附件服务把多帧压成单帧）。
- 图片大时会被自动降采样 ⇒ 拼图总宽 768；细节不要寄希望于拼图，必须进窗口看单帧。
- 旧视频常是 12.5 fps（`video_max_frames` 稀疏化）⇒ `--window` 直接拒绝；
  用第 0 节的评审配置重渲。
- 监视器一律只读、不得写文件（临时目录也不行）；要放大用 PIL **在内存里**做。
- n=1 必须写进结论；单次摆动判不了“时长”这类可平均的量。
- 训练结束先渲视频再派评审；评审是只读快操作，不要在训练中途占着上下文等结果。
