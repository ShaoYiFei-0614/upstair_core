# `scripts/teleop.py` — 外部控制器遥控（遥感操控演示）

对应代码：`scripts/teleop.py`。指令接口的设计动机见 `doc/env.md` 与
`experience.md` §13、§17；本文只讲抽象结构。

## 职责

演示 `Go2StairsEnv` 的**外部指令接口**：策略只负责跟踪指令，指令由一个「看着地形
打方向」的控制器给出。控制器可以读地形与机身位置 —— 遥操作本来就有这些信息，
**盲走约束只限制策略的观测**。

## 核心抽象

### 两个指令入口的分工

- `set_commands(...)` — 改**采样范围**，这里只用来把范围放开到控制器输出上限
  （课程范围之外的指令策略没见过，量到的不是课程内性能）。
- `set_command_now(...)` — 每个控制步改写**当前值**（`hold=True`），是控制器的高频
  入口；写入后必须重取一帧观测（环境只刷新自己内部那帧）。

### 两个控制器

- `StairController` — 闭环看着地形打方向：远处直走、接近楼梯先对准入口、
  爬升阶段沿中线对齐（偏航对准 + 横移回中）、越过顶端收住。
- `HoldController` — 把一条固定指令钉死跑满回合，是量「跟踪某个指定指令」最干净
  的判据（指令不随状态变化，统计偏差就是纯跟踪误差）。

### 量程的三级回退（`command_limits`）

驱动某一级时用的 `(vy_max, yaw_max)` 按 `plan.json`（训练实际下发值）→
`summary.json` → 当前 `config.yaml` 同名级 → 演示默认值 的顺序取。权重自带的
`_env.json` 只记配置基线，**不能**当训练量程用。

## 与 cmd_demo 的分工

teleop 是「控制器闭环看着地形打方向」；cmd_demo 是「开环给一串分段恒定指令」，
专门量跟踪能力。
