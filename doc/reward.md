# `robotdog/reward.py` — 奖励数学（唯一来源）

对应代码：`robotdog/reward.py`。每个权重堵住哪种失败、每个默认值的实测依据，
都在 `experience.md`（§2、§12–§16、§21）；本文只讲抽象结构。

## 职责

仓库里**所有**奖励数学的唯一住所：`RewardConfig`（权重与阈值）、
`compute_reward`（逐步奖励 + 逐项明细 + 终止奖励）、两个势函数状态机。
它不是纯函数 —— 几个势函数项依赖环境上的记忆字段才能做到「总量有界、不可刷分」，
所以会写 `env` 的这三个字段：`_peak_terrain_height`、`_probe_best`、`_probe_count`。
**不能为了对比而重复调用。**

## 三部分

### 1. `compute_reward` — 逐步结算

各项共用一个跟踪形状 `track_shape(x, tail)`：`x = |误差|/量程` 的单调递减函数，
死区内线性、死区外接线性尾项。三条契约性质：在 x=1 处连续、全程单调递减
（尾项必须是线性而非二次 —— 二次减项会把误差推向更大，见 `experience.md` §13）、
惩罚有下界（调用处 `max(-1, ·)` 兜底）。

项分组：

| 组 | 项 | 结构要点 |
| --- | --- | --- |
| 指令跟踪 | `forward_vel`、`command_follow`（横向+偏航求和） | 绝对误差窗口；目标取**本步真实采样的指令**；横向按量程门控、偏航恒在（量程下限 `yaw_range_floor`） |
| 姿态/能耗 | `orientation`、`torque`、`base_height`、`joint_vel`、`action_rate`、`joint_limit`、`alive` | 常规成形项，全部逐步有界 |
| 步态 | `foot_lift`、`air_time` | 足端三维速度门控；air_time 在落地那一步结算 |
| 碰撞 | `body_collision`、`leg_collision` | 逐步、有界、不终止回合 |
| 爬升 | `stair_progress` | **一次性结算**：只在四足支撑面刷新本回合最高时付增量 |
| 试探 | `probe_lift` | 只在被阻挡时结算的势函数塑形 |

**前进速度的参照系规则**（`_forward_speed`）：楼梯级用课程方向（世界系 x），
平地级用机身系 x。因为「前方」在楼梯上只能是课程方向 —— 只跟踪机身系时，
掉头背对楼梯走开就是最优解（`experience.md` §21.14）。

### 2. 势函数塑形（probe_lift）

只结算「被阻挡期间的摆动峰值又比该足历史最好高出多少」。三条性质：
**总量有界**（≤ 权重 × 可达峰值 − 起算线）、**不可刷分**（重复同样高度拿不到
第二次）、**有梯度**（每一步抬得更高都被记录）。起算线只跟「策略当前能抬多高」比，
不跟台阶高走（门槛不可达 ≡ 权重为零，`experience.md` §15）。

注意：**「总量有界」不等于「不可刷分」** —— 一次性结算只保证同一高度不重复付钱，
参照量本身必须是任务真正想度量的事件（脚踩上去了，不是躯干探过去了，
`experience.md` §21.13）。

### 3. 状态机（`env.step` 在奖励结算前调用）

- `track_swing_peak(env, foot_contact)` — 逐足维护「本次摆动期的最大离地间隙」。
  清零必须发生在奖励结算**之后**（落地帧保留旧峰值），否则结算读到的是被清掉的
  旧值（`experience.md` §15 尝试一）。
- `update_probe_state(env)` — 「被阻挡」判定与锁存：有前进指令但实测速度远低于
  指令即判阻挡，直到支撑面刷新或速度恢复才解除（撞立面时会前后晃，不锁会一步一跳）。

## 奖励账目恒等式

`compute_reward` 返回的 `terms` 每项已乘权重，`sum(terms.values())` 即未加终止奖励
的逐步奖励；env 侧把 `terminal` 并入后，逐步奖励恒等于 `sum(terms.values())`。
所以逐项拆解可以安全地相加对账。

## 改奖励的纪律

1. **先算「机器人什么都不做」时这项给多少分** —— 与任务无关却每步都付的正项
   会把站桩变成局部最优（这个错犯过两次，`experience.md` §12、§13.3）。
2. **奖励项上线前量它的噪声底** —— 读的量被步态振荡主导时，一半权重进了策略
   控制不到的通道（§16）。
3. **量它的可达性** —— 永远拿不到的奖励与权重为零是同一件事（§15）。
4. 改完跑 `.tmp/eq_check.py` 等价回归（`agent.md` §7）。
