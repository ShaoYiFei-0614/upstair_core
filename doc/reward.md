# `robotdog/reward.py` — 奖励数学（唯一来源）

对应代码：`robotdog/reward.py`。每个权重堵住哪种失败、每个默认值的实测依据，
都在 `experience.md`（§2、§12–§16、§21）；本文只讲抽象结构。

> 逐项清单（权重/阈值/开关/课程覆盖/日志项，只整理不精简）：`doc/reward_inventory.md`。

## 职责

仓库里**所有**奖励数学的唯一住所：`RewardConfig`（权重与阈值）、
`compute_reward`（逐步奖励 + 逐项明细 + 终止奖励）、两个势函数状态机。
它不是纯函数 —— 几个势函数项依赖环境上的记忆字段才能做到「总量有界、不可刷分」，
所以会写 `env` 的这三个字段：`_peak_terrain_height`、`_probe_best`、`_probe_count`。
**不能为了对比而重复调用。**

## 三部分

### 1. `compute_reward` — 逐步结算

各项共用一个跟踪形状 `track_shape(x, tail)`：`x = |误差|/量程` 的单调递减函数，
死区内线性、死区外接线性尾项。三条契约性质：在 x=1 处连续、全程单调递减
（尾项必须是线性而非二次 —— 二次减项会把误差推向更大，见 `experience.md` §13）、
惩罚有下界（调用处 `max(-1, ·)` 兜底）。

项分组：

| 组 | 项 | 结构要点 |
| --- | --- | --- |
| 指令跟踪 | `forward_vel`、`command_follow`（横向+偏航求和） | 绝对误差窗口；目标取**本步真实采样的指令**；横向按量程门控、偏航恒在（量程下限 `yaw_range_floor`） |
| 姿态/能耗 | `orientation`、`torque`、`base_height`、`joint_vel`、`action_rate`、`joint_limit`、`alive` | 常规成形项，全部逐步有界 |
| 步态 | `foot_lift`、`air_time` | 足端三维速度门控；air_time 在落地那一步结算 |
| 碰撞 | `body_collision`、`leg_collision` | 逐步、有界、不终止回合 |
| 爬升 | `stair_progress` | **一次性结算**：只在四足支撑面刷新本回合最高时付增量 |
| 试探 | `probe_lift` | 只在被阻挡时结算的势函数塑形 |

**坐标系统一（2026-10-13）**：指令在世界系给定，每步经 `command_body()` 投影到
机体系后与机身系实测比较 —— 掉头背对指令方向时，机体系指令立即变成「后退」，
误差自然惩罚它。§21.14 的「楼梯级用世界系/平地级用机身系」地形分支
（`_forward_speed`）由此删除：世界系指令 + 机体系投影在结构上关闭了
「掉头走开」漏洞，不再需要按地形切换参照系。

### 2. 势函数塑形（probe_lift）

只结算「被阻挡期间的摆动峰值又比该足历史最好高出多少」。三条性质：
**总量有界**（≤ 权重 × 可达峰值 − 起算线）、**不可刷分**（重复同样高度拿不到
第二次）、**有梯度**（每一步抬得更高都被记录）。起算线只跟「策略当前能抬多高」比，
不跟台阶高走（门槛不可达 ≡ 权重为零，`experience.md` §15）。

注意：**「总量有界」不等于「不可刷分」** —— 一次性结算只保证同一高度不重复付钱，
参照量本身必须是任务真正想度量的事件（脚踩上去了，不是躯干探过去了，
`experience.md` §21.13）。

### 3. 状态机（`env.step` 在奖励结算前调用）

- `track_swing_peak(env, foot_contact)` — 逐足维护「本次摆动期的最大离地间隙」。
  清零必须发生在奖励结算**之后**（落地帧保留旧峰值），否则结算读到的是被清掉的
  旧值（`experience.md` §15 尝试一）。
- `update_probe_state(env)` — 「被阻挡」判定与锁存：有前进指令但实测速度远低于
  指令即判阻挡，直到支撑面刷新或速度恢复才解除（撞立面时会前后晃，不锁会一步一跳）。

### 尺度审计结论（同日）

* **整体尺度不过大**：所有逐步项都被形状下界 `max(−1, ·)` 与 `overspeed_cap`
  约束在 **±10 × 权重带**内；绝对量由 `VecNormalize`（norm_reward）吸收。
* **两个稀疏事件刻意大**（不 scaling）：`stair_progress` 单事件 +36~+180 与
  `termination ±5000` —— 前者是 §21.10 校准的爬升信号（且 §23 显示爬楼梯度
  刚建立，下调会削弱它），后者是 §19.2 的「防早摔」下界。
* **四个死项是瞬态保险丝**（不 scaling）：`base_height` / `joint_vel` /
  `action_rate` / `joint_limit` 在 2 Hz 稳态下 ≈0，姿态发散或动作抖动时才
  起作用 —— 它们存在就是为了那种时刻。
* **已应用的 scaling**：`success 50 → 500`（§23.7 诊断的「爬完 vs 摔在半路」
  账面失衡；登顶从 +50 提到与 stair_progress 总量同量级，仍为 termination
  的 1/10）；`yaw_zero_gain` 从硬编码提为字段（公式显式化，当前值不变）。
  两者都待下一轮训练验证。

## 足底触觉相位条件策略（TactileStep，2026-10-20）

数据面在 `robotdog/tactile.py`（测量 + 四相位机，设计见 `doc/tactile.md`）；本节只讲
`compute_reward` 第 11 段的结算。**四个权重默认全 0，且四项都为 0 时整段跳过** ——
不产生键、不产生计算，逐步奖励与旧实现逐位一致（`tests/test_tactile.py` 钉住）。

> 2026-10-21 更新：新增 `tactile_slip`，并给 `tactile_stance` 加「真的在前进」门控。
> 背景：l0/l1 的 A/B 里 `l1_st`（只加 stance）训练窗口**全级 0%**、回放蹲在第一级不动 ——
> 因为 stance 按帧无条件发奖，而「零指令通道」的 `command_follow` 还白给正项，
> 「蹲稳不动」成了回报最高的局部最优（`doc/introduce_tactile.md` §8.3）。

| 项 | 门控 | 逐足公式（再对 4 足取 mean） | 默认 |
| --- | --- | --- | --- |
| `tactile_prelanding` | `phase==PRELANDING` | `w·clip(−vz/prelanding_vz_ref, 0, 1)²` | `0.0` |
| `tactile_impact` | `phase==LANDING` | `w·[clip(F̄/impact_force_ref,0,2) + clip(\|ΔF̄\|/impact_delta_ref,0,2) + clip(peak/impact_peak_ref,0,2)]` | `0.0` |
| `tactile_stance` | `phase==STANCE` **且**前进门控 | `w·[clip(Ā/stance_area_target,0,1) + margin − clip(cop_jump/stance_cop_jump_ref,0,1)] · min(1, vx_fwd/stance_min_vx)` | `0.0`（`stance_min_vx=0` 即无门控） |
| `tactile_slip` | `phase==STANCE` | `w·clip(‖Δp_xy‖/slip_ref, 0, 1)`（Δp 为本控制步足端水平位移） | `0.0`（`w<0` 为罚） |

量纲与有界性（便于配权重时估量级）：

- `tactile_prelanding ∈ [w, 0]`（w 为负；平方项在 `−vz ≥ prelanding_vz_ref` 时饱和）；
- `tactile_impact ∈ [6w, 0]`（三个分量各在 [0,2]，mean 不放大）；
- `tactile_stance ∈ [−w, 2w]`（`area+margin−jump` 每足 ∈ [−1, 2]，再乘前进门控 ∈[0,1]）——
  **不是纯正奖励**：CoP 跳变打满且面积/margin 很小的一帧可以为负；
- `tactile_slip ∈ [w, 0]`（w 为负；`clip(Δ/slip_ref,0,1)` 在单步位移 ≥ `slip_ref` 时饱和；
  `slip_ref=0.005` m 是「站稳时单步抖动」量级，实测支撑相 mm 级滑移会接近 0.5–1.0 归一化）；
- 四项都**逐控制步**结算，按四足 mean（不是 sum）—— 与 `air_time`/`foot_lift` 同口径，
  避免「脚数多就分多」的偏差。

参考量级来自论文与本仓探针：`F̄` 峰值 ≈0.8 体重（6cm 台阶、站立/小步），`Ā` 峰值 ≈0.16
（足底面积占比），所以默认把 impact 参考取 3.0 体重、stance 目标取 0.60 —— 训练初期
这些项应当**接近 0/小正**，一旦频繁打满说明阈值离当前行为太远（先标定再开大）。

**为什么 stance 必须门控 + 滑移要单独罚**（`l1_st` 的教训，`doc/introduce_tactile.md` §8.3）：

- `tactile_stance` 按**帧**结算。不支持前进时，原地蹲低就能拿满（面积大、margin 大、CoP 稳），
  而 `command_follow` 在**零指令通道**还会白给正项（`cmd.vy==0`/`cmd.wz==0` 时误差恒 ≈0 ⇒
  `track_shape` 满额）⇒ 「蹲稳不动」总回报超过真正爬楼。门控用机身系前向速度
  `vx_fwd = max(0, base_lin_vel_body[0])`，`stance_min_vx>0` 时按 `min(1, vx_fwd/stance_min_vx)`
  线性打折，**必须同时看 `mean_distance`**（否则短促摆动也可能骗过瞬时门控）。
- `cop_jump`/`margin` 是**压强分布**的平滑性/裕度，**不是足端滑移**。要罚「支撑相足端在地上滑」
  必须用 `tactile_slip`（足端位移）；实测 `l1_st` 的 `cop_jump` 反降而 slip 反升，说明两者
  不可互替。
- 与 `follow_zero_baseline` 配套：打开后，零指令通道（`|vy_cmd| < zero_cmd_eps_vy`、
  `|wz_cmd| < zero_cmd_eps_wz`）的跟踪项扣 1（不再白给）。**必须用死区**——`cmd_body` 含
  `command_wander_std` 的 OU 扰动与楼梯引导注入，楼梯级几乎恒非 0，`== 0.0` 判据永不触发。

⚠ 与既有 contact 组（`foot_scuff`/`foot_impact`/`load_share`/`com_margin`）不要同时开同类项：
那四项按「接触事件」直接罚/奖（已否决、默认关），本组按「相位」结构化结算，同时开会
重复惩罚同一物理事件。

## 奖励账目恒等式

`compute_reward` 返回的 `terms` 每项已乘权重，`sum(terms.values())` 即未加终止奖励
的逐步奖励；env 侧把 `terminal` 并入后，逐步奖励恒等于 `sum(terms.values())`。
所以逐项拆解可以安全地相加对账。

## 改奖励的纪律

0. **新项要过「双条件消融」关**（2026-10-14，§23.27）：双臂 A/B（楼梯全灭）
   的三个新项（`foot_hold` / `pitch_posture` / probe 低足门控）单独看每个的
   单元验证都通过、最终策略账目里也几乎不结算 —— 但它们与**平地阶段**的
   交互（pitch 咬姿态分布）+ 对 stair3 探索期的干扰，2×2 消融才暴露出来：
   好权重 + 摘三项 = 86% 复现，其余三格全 0%。教训：**单元验证 ≠ 训练验证**；
   新奖励项上线前后必须各跑一次 stair3 短课程（250k 足够）对照。

1. **先算「机器人什么都不做」时这项给多少分** —— 与任务无关却每步都付的正项
   会把站桩变成局部最优（这个错犯过两次，`experience.md` §12、§13.3）。
2. **奖励项上线前量它的噪声底** —— 读的量被步态振荡主导时，一半权重进了策略
   控制不到的通道（§16）。
3. **量它的可达性** —— 永远拿不到的奖励与权重为零是同一件事（§15）。
4. 改完跑 `.tmp/eq_check.py` 等价回归（`agent.md` §7）。
