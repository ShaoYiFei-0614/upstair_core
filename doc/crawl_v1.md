## 1. 动作设置

### 1.1 流水线（residual）

```
target_joint = home + gait_gain · gait.radians(θ_t) + action_scale · a_t
target_joint = clip(target_joint, act_low, act_high)
```

| 项 | 值 | 说明 |
| --- | --- | --- |
| `home` | `home_angles`（12 维标称站立，机身 0.27 m） | `meta.home_joint_angles` |
| `gait_gain` | 1.0 | 先验的全局权重 |
| `action_scale` | **0.60 rad** | 策略可偏离先验多少 |
| `a_t` | `Box(-1, 1)^12`，`step` 里先 clip 到 ±1 | 策略输出 |

**为什么两个 `action_scale` 分开**：`gait.action_scale`（artifact 里，= 1.0）表示
**先验本身多大**，`cfg.action_scale`（= 0.60）表示**策略能偏离它多少**。共用一个尺度会
让探索噪声随先验幅值一起缩放，瞬间失稳（`env.py:1129` 的 docstring）。

**residual 的另一半**：`_last_traj` 在 residual 模式下存放的是**上一步动作** `a_{t-1}`
（`env.py:1268`），在 `gait_params` 模式下存放的是上一步生成的关节偏移轨迹。

### 1.2 先验步态：两套 artifact，按地形切换

切换规则（`Go2StairsEnv._active_gait`，`env.py:994`）：

```python
return self.cfg.gait_stair if (self.stair.n_up > 0 and self.cfg.gait_stair) else self.cfg.gait
```

| 字段 | 平地 `artifacts/trot_natural167.json` | 楼梯 `artifacts/crawl_125.json` |
| --- | --- | --- |
| `freq` [Hz] | 1.67 | **1.25** |
| `amp_th` [rad] | 0.40 | 0.40 |
| `amp_ca` [rad] | 0.50 | **0.70** |
| `ph_th` [rad] | −1.400 | −1.400 |
| `ph_ca` [rad] | 0.0853 | 0.0853 |
| `off_th` [rad] | 0.12 | 0.12 |
| `off_ca` [rad] | 0.0 | 0.0 |
| `calf_shape` | `sin` | `sin` |
| `swing_frac` | 无（= 默认 0.5，不扭曲） | **0.25** |
| `leg_phase` | 对角反相 `[0, π, π, 0]` | **四分之一错相** `[0, π, 3π/2, π/2]` |

三条结构事实（不是调参，是几何决定的）：

1. **踏面 0.30 m < 前后足间距 0.367 m** ⇒ 四足**无法同踩一级**，必须跨级站立
   （前脚高一级、后脚低一级）。这就是楼梯必须用**爬行**（一次一足、三足支撑）而不是
   小跑的**结构性**原因。
2. **`swing_frac = 0.25`** 是相位扭曲：把摆动期压到周期的 1/4，支撑相拉长，脚落定后
   有更长的稳定窗口——正是跨级登踏需要的。
3. **`amp_ca = 0.70` 是可迁移的解，不是最好看的解**。0.85 让 3 cm 姿态明显变好
   （后腿参与、抬升 0.7–1.2 倍台阶高），但跨高度迁移崩塌（4.5 cm → 0%）。
   「观感」与「可迁移性」在**先验幅值**这一维上冲突，要兼得必须换路线（条件化或
   奖励侧），不能调这里。

### 1.3 相位与频率

- 相角 `θ = 2π · f_eff · t`，`t` 为回合内秒数（`_gait_theta`，`env.py:1060`）。
- `f_eff`（`_gait_freq_eff`）：楼梯级且配了 `gait_stair` ⇒ 先验自带频率 **1.25 Hz**；
  平地 ⇒ 先验 json 频率 **1.67 Hz**。
- **产生器用的与观测报的必须是同一个 θ**（马尔可夫性）；`foot_lift` 的门控与
  `air_time` 的目标也以同一个 `f_eff` 做频率归一（`§23.29` 的「二分」教训）。

### 1.4 先验状态门控

| 项 | 值 | 说明 |
| --- | --- | --- |
| `prior_gate_on_stand` | True | 站立时先验向 `floor` 衰减 |
| `prior_gate_on_block` | **False** | 受阻时**不**衰减（楼梯上受阻是常态，衰减会停掉爬楼动作） |
| `prior_gate_tau` | 0.3 s | 平滑时间常数 |
| `prior_gate_floor` | 0.0 | 目标值 |

### 1.5 已归档：`gait_params` 模式（P2）

把 8 维**步态参数**（前/后对各 6 项）当作动作，经 sin 结构生成轨迹。楼梯上两次全败
（旧奖励 4%、新奖励 0%，`§23.27`），已归档不再使用。代码保留在
`_gait_traj_from_params`，`action_mode` 一改即可复现。

### 2.1 逐维账（`history_len = 1` ⇒ 共 **53 维**）

> ⚠ `config.yaml` 里 `obs` 段上方那句「55 维」的注释是**旧的**（把 `base_frame_size`
> 的 42 拆错了）。以本表为准：**42 + 3 + 3 + 2 + 1 + 2 = 53**。
> `runs/*/model_final_env.json` 记录的 `base_frame_size = 42` 与四个开关可交叉验证。

**第 6、7 两块没有开关**（`_obs_frame` 里写死）：它们是指令跟踪的「实测」与「指令」
两侧，缺一不可。要改只能改代码，不能改配置。

### 2.2 三个被明确禁止 / 撤下的项

| 项 | 状态 | 原因 |
| --- | --- | --- |
| `base_height` | **构造期直接抛异常** | 它是「机身相对正下方地形的高度」，含**地形真值**，破坏盲走。分支已整体删除（不是关掉——「约定不是保证」，`§11`） |
| `gait_cmd` | 撤下（`false`） | 步态指令条件化在四轮训练中**系统性把 RL 推向贴地**（4.8–7.0 cm vs 无条件化的 26.5 cm）：条件给了策略一个「小残差跟随先验摆动」的出口，`foot_lift` 的梯度推不动它（`§23.29`）。band 字段保留，关闭时仍用于采样，只喂先验生成 |
| `history_len = 10` | 改为 **1** | 50 Hz 下相邻帧几乎相同，10 帧 = 500 维几乎全是冗余。实测 1 帧**不亏**：课程内逐级不差、3 cm/6 cm 还更好（92% vs 62%） |

### 2.3 观测的硬约束

- **观测维数在整条课程里必须恒定**：课程只能改指令的**范围**，不能开关那 3 维指令观测
  ——否则 PPO 的网络与 `RolloutBuffer` 会对不上。
- **奖励读的量必须同时进观测**：`command_follow` 读的是 `vel_filter` 那 2 维同一批量，
  `gait_phase` 报的是产生器实际用的相位。任何「只改奖励不改观测」都会把滤波器/时钟状态
  藏起来，破坏马尔可夫性。

## 3. 奖励设置

奖励数学的唯一来源是 `robotdog/reward.py`，`sum(terms.values()) + terminal` 就是
`env.step` 返回的标量。**终止奖励单列**（它取决于「成功登顶还是摔倒」）。

### 3.1 指令跟踪（4 项）

共同形状 `track_shape(x, tail)`（`reward.py:113`）：`x = |误差| / 量程`，
`x ≤ 1` 线性死区 `1 − x`；`x > 1` 换线性尾项 `−tail·(x−1)`。契约：在 `x = 1` 处连续、
**全程单调递减**（尾项必须线性——二次减项在 `x > 1` 后先增后减，等于把误差推向更大，
`§13`）、惩罚有下界（调用处 `max(-1, ·)` 兜底）。

| 项 | 权重 | 量程 / 形状 |
| --- | --- | --- |
| `forward_vel` | **10.0** | 量程 = `forward_track_window` = 0.25 m/s（**绝对**，不按指令归一） |
| `forward_overspeed` | 1.0 | 超速侧额外斜率：每 1 m/s 扣 `forward_vel / overspeed_range`(0.45)，倍率上界 `overspeed_cap` = 2.0 |
| `lateral_vel` | 6.0 | 量程 = `0.5 · max(vy_max, 0.15)`，**恒在、不门控** |
| `yaw_rate` | 4.0 | 量程 = `0.5 · max(yaw_max, 0.30)`，**恒在、不门控**；`cmd.wz == 0` 时误差乘 `yaw_zero_gain`(1.5) |

三条必须记住的设计约束：

1. **量程必须是绝对量、不能按指令大小归一化**：相对误差下指令带一窄，站着不动就几乎
   满分（无先验三臂全部收敛到常数输出，站桩 +4.93/步）。
2. **横向与偏航两项求和，不取 max**：取 max 时误差小的那项会盖掉另一项的梯度
   （实测取 max 的版本偏航相关性 r = −0.085、斜率 −0.006，等于偏航没学）。
3. **两个通道都恒在**（`vy_max=0` / `yaw_max=0` 的级别也照常结算）：门控级别里没有任何
   一项读 wz，策略学会以 −0.608 rad/s **恒定自转**并冻住（`§23.10`）。

指令在执行前统一**投影到机体系** `env.command_body()`：执行器只产生机体系速度，世界系
指令在机身转向后含义不变。

### 3.2 姿态与能耗（4 项）

| 项 | 权重 | 公式 |
| --- | --- | --- |
| `orientation` | **−1.2** | `−1.2 · (roll² + pitch²)` |
| `pitch_posture` | **0.0（关）** | `w · min(max(0, −pitch − tol), cap)`，`tol = 0.14 + 1.2·台阶高` |
| `torque` | −1.5e−4 | `−1.5e−4 · Στ²` |
| `joint_vel` | −2.0e−5 | `−2.0e−5 · Σq̇²` |
| `action_rate` | −0.02 | `−0.02 · ‖a_t − a_{t−1}‖²` |
| `joint_limit` | −0.5 | `−0.5 · Σ max(0, lo−q) + max(0, q−hi)` |

`pitch_posture` **为什么是 0**：死区 0.14 rad 覆盖不住健康姿态分布（sub9_v5 平地
pitch −7°±5.7°，49–60% 时间在死区外），`flat_4` 出厂 76% → 18%；把死区放宽到不伤分布
（≥0.35 rad）又罚不到 −0.18 rad 的目标行为——该形式在平地无解。**平地抬头改用课程顺序
解**（回归级，待做）。字段保留作楼梯级极端抬头的实验位。

### 3.3 抬脚与试探（3 项）

| 项 | 权重 | 形状 |
| --- | --- | --- |
| `foot_lift` | 0.9 | `w · mean(gate · lift)`，`gate = clip(足端三维速度 / gate_speed, 0, 1)`，`lift = clip(clearance / target, 0, 1)` |
| `foot_lift_target` | 0.08 | 目标**下限**；有效目标 = `max(0.08, foot_lift_step_ratio × 台阶高)` |
| `foot_lift_step_ratio` | 1.4 | 同上 |
| `foot_lift_gate_speed` | 0.25 m/s | 楼梯固定 0.25；平地乘 `f_eff / 1.67` 归一 |
| `probe_lift` | 0.0（基线） | **势函数**：受阻时逐足结算「摆动峰值比该足历史最好又高出多少」，总量有界、不可刷分 |
| `probe_lift_target` | 0.06 m | 进展的起算线，取普通步态峰值带（0.06–0.12）的上沿 |
| `probe_blocked_frac` | 0.30 | 实测前进速度 < 该比例 × 指令速度 ⇒ 判定「被阻挡」 |
| `foot_hold` | **0.0（关）** | 受阻态驻留势函数 `Φ = 台面脚数 × 台阶高`，按 ΔΦ 结算 |

- **门控用三维足端速度**：只看水平分量会奖励「快速的贴地平扫」，同时砍掉高台阶需要的
  慢速抬腿。
- **频率归一必须地形二分**：平地随 `f_eff` 归一（低频慢摆同样开门），楼梯固定 0.25
  （归一后在楼梯上让「立面贴地蹭速」达标 ⇒ 假梯度、3 cm 崩，`§23.29`）。`air_time` 的
  目标用同一套二分。
- **`foot_hold` 为什么关**：它与 stair3 探索期的「受阻 → 抬脚再爬」转移**对打**
  （抬脚吃即时罚），是双臂 A/B 楼梯全灭的两个条件之一。驻留是美观/功耗诉求，
  重引入必须过 stair3 250k 对照关。

### 3.4 碰撞与安全（3 项）

| 项 | 权重 | 形状 |
| --- | --- | --- |
| `body_collision` | **−1.2** | `−1.2 · [躯干接触地形]`，逐步、有界，**不终止回合** |
| `leg_collision` | −0.25 | `−0.25 · [髋/大腿/小腿接触地形]`，逐步、有界，**不终止回合** |
| `base_height` | −2.0 | `−2.0 · (base_z − 地形高 − 0.27)²` |

**接触类信号一律不终止回合**（`_terminated` 的 docstring）：躯干接触的代价由
`body_collision` 逐步承担；历史的「连续接触 N 步判摔」规则从未生效且会误杀上台架时的
正常蹭立面。膝/胫接触只扣分、不终止——机器人可以在高楼梯上继续尝试，这正是保留试错的
原因。

### 3.5 步态成形、爬升与结局（5 项）

| 项 | 权重 | 形状 |
| --- | --- | --- |
| `air_time` | 0.6 | 落地那一步结算 `w · Σ[(air − target)⁺ − (air − air_time_max)⁺] · [落地]` |
| `air_time_target` | 0.30 s | 楼梯级固定 0.30；平地乘 `f_eff / 2.0` |
| `air_time_max` | 0.60 s | 超出部分倒扣 |
| `stair_progress` | **1200.0** | **一次性**：只在支撑面刷新本回合最高时付增量 `1200 · Δ(四足支撑面最高)` |
| `alive` | 0.15 | 每步固定 +0.15 |
| `success` | **500.0** | 登顶一次性（`env._reached_top` 粘性） |
| `termination` | **−5000.0** | 摔倒一次性：`−5000 · (1 − 0.5 · 爬升完成度)` |

- `stair_progress` 的**参照面是四足支撑面**（`env._support_height()`）而不是躯干 x：
  原来「躯干探过立面就收钱、四只脚可以全在地面」，9 cm 上能白拿 +108，正是记过的退化
  路径；提到 1200 等于把它放大 400 倍。
- `termination` **必须远大于单步奖励动态范围 × 回合步数**，否则「提前摔倒」成为最优解
  （实测把摔倒率从 0% 训到 100%、平均步数从 1000 掉到 75）。−5000 与 `success` 的比例
  是 1 : 10，`success` 又与 `stair_progress` 总量同量级（爬完 15 cm ≈ +1440 + 500）。
- `termination` 的**进度分级减免**：高处的摔倒罚得轻——进展已由 `stair_progress` 逐级
  支付，全额罚会把「高处的尝试」罚得比「脚下空耗」还重。

> ⚠ 上表是**未归一化**的原始数字。`ppo.norm_reward = true` 会先除 `ret_rms` 再 clip
> （默认 10），优化器看到的是**相对**量级，不是 1440、5000 这些绝对值。

### 3.6 课程的奖励覆盖（`curriculum.reward_overrides`）

九级课程（`config.yaml`，**逐级抬高抬腿激励**）：

| 级 | flat×4 | 3 | 4.5 | 6 | 7.5 | 9 |
| --- | --- | --- | --- | --- | --- | --- |
| `foot_lift` | 0.9 | 1.0 | 1.05 | 1.2 | 1.3 | 1.4 |
| `foot_lift_step_ratio` | 1.4 | 1.6 | 1.7 | 1.8 | 1.9 | 2.0 |
| `probe_lift` | 0 / 0 / 0 / 0.4 | 0.6 | 0.75 | 0.9 | 1.05 | 1.2 |
| `forward_overspeed` | 0 / 0 / 0 / 0.3 | 0.6 | 0.8 | 1.0 | 1.0 | 1.0 |
| `yaw_rate` | 8.0 / 6.0 / 6.0 / 4.0 | 4.0 | 4.0 | 4.0 | 4.0 | 4.0 |

**规律**：越高的台阶越鼓励抬腿与试抬（低台阶不需要，高台阶缺的正是这个）。前三级关掉
超速惩罚并抬高偏航权重——转向探索必然要加速，超速惩罚会惩罚它，而「转向」在账面上必须
压过「跑得快」才学得出来。

（其余键与基线一致：`forward_overspeed = 1.0`、`yaw_rate = 4.0`。奖励基线本身与

## 4. 终止与成功判据

| 事件 | 判据 | 奖励 |
| --- | --- | --- |
| **摔倒** | `base_z − 参照面 < 0.15` **或** `abs(roll) > 1.0` **或** `abs(pitch) > 1.0` | `termination · (1 − 0.5·完成度)` |
| **超时** | `step_count ≥ 1000` | 无终止奖励 |
| **成功** | 见下（本回合内**粘性**，早先的摔倒仍然算失败） | `+500` |

**成功判据分两种地形**（`env._success_reached`，`env.py:636`）：

- **楼梯段**：`base_x > stair.up_end_x` **且** 机身下方地形高 ≥ `crest_height`
  ——即**真的站在顶面**，不是越过了 x 坐标。
- **平地段**：**撑满整个回合** 且 脱靶步数占比 ≤ 0.30 且（最差可变轴的）指令-实测
  **相关系数 ≥ 0.30**。三个条件缺一不可：只看时长会奖励「原地不动」，只看随动会奖励
  「活到一半就摔」，只看容差不看相关性则会奖励「输出常数」。脱靶容差：
  `vx 0.35 / vy 0.12 / wz 0.40`（后两者读**滤波后**的量）。

- 摔倒判据的**参照面 = 四足下方最低地形**（`terminate_height_ref = "support"`）：机身
  下方地形是躯干 x 的阶梯函数，相邻帧跳一整个立面会产生**幽灵摔倒**（`§1.4`）。
- 躯干碰撞体的最低点在 0.118 m，所以 0.15 留了 3.2 cm 余量。
- ⚠ 平地在**训练统计**与**回放**里用的都是这条判据——所以「平地成功率 10%」多半是
  指令跟踪脱靶，不是走不动。
