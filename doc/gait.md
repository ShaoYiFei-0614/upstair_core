# `robotdog/gait.py` — 开环步态先验

对应代码：`robotdog/gait.py`。标定数据与「为什么速度参数化长这样」见
`experience.md` §19–§21；本文只讲抽象结构。

## 职责

为残差 RL 提供一条**可检查的**周期关节轨迹。没有它，PPO 从零学不出步态
（随机关节抖动不产生净推进，前进奖励在出现协调步态之前是平的）。

## 核心抽象

### 残差流水线

```
target = home + gait_gain · gait.radians(t) + action_scale · action
```

先验的幅值单位是**归一化动作单位**（与策略动作同尺度），乘 `GaitParams.action_scale`
才变弧度 —— 与策略的 `EnvConfig.action_scale` **刻意分开**：共用一个尺度会让策略的
探索噪声随先验一起缩放。`radians()` 与 `actions()` 的分工：前者是环境用的弧度接口，
后者是归一化单位的内部实现。

### GaitParams 是数据，不是代码

一条先验 = 频率 + 大腿/小腿的幅值/相位/偏置 + 腿相位模式 + 小腿波形。
它以 JSON 文件形态存在 `artifacts/` 下（换结构不必改源码）；`normalize()` 在
加载与保存时把它裁剪回物理可行域，核心约束是 `|off| + amp ≤ 1`。

**注意这条约束的推论**：先验的「振幅」不是自由度，它是 `(amp, off)` 在单纯形上的
一个点。当某条 artifact 的 calf 通道出厂就顶在边界上时，全局幅值缩放对它是
**结构性地无效**（`experience.md` §21.15.4）—— 要改抬腿高度只能动结构
（`leg_phase` / `calf_shape` / `freq`）或让残差去补。

### 速度参数化（`scale_for_speed`）

把期望前进速度映射为先验幅值缩放：实测行走支上 `v(s)` 是干净的线性函数，反解即得。
两个裁剪边界都有物理含义：下侧是**行走支下沿**（再小先验摔倒，中间那段缩放
不存在稳定解）、上侧是 `normalize()` 开始整体再缩放的边界。低于下沿的指令段
先验仍以下沿速度走，那一段靠策略残差刹车。

⚠ **标定曲线是先验特定的**：`v(s)` 在 5.48 Hz 的 trot 上测得；换步频/换先验
必须重做 §20 的标定。当前出货配置（2026-10-13 起）`gait_speed_track: false`，
使用 2 Hz 自然步态（`artifacts/trot_natural.json`，零残差 ≈0.22 m/s、平地
3 seed × 40 s 全存活）—— 速度参数化机制保留但闲置。

运行期动态缩放放在 `_scale_dyn` 字段：`radians()` 临时应用、用完还原，
**不进任何配置文件**（`to_dict()` 会剔除）—— 它是每步按当前指令现算的，写进
配置只会让下次加载带一个过期数字。

### 先验的定位（重要）

**先验不得成为楼梯的解。** 搜出来过一条满幅零残差就能爬楼的 walk 先验
（`artifacts/walk_stairs.json`）—— 它被降级为实测发现而非出货配置：先验已解决的
任务上继续训 RL 只会把它弄坏（`experience.md` §21）。出货先验（trot）提供稳定的
行走节律，爬楼必须由 RL 从奖励梯度里学出来。

## 序列化

`to_dict` / `from_dict` / `load_gait`：JSON 往返保持字段类型；`from_search_json`
读参数搜索结果文件。`GaitParams.static()` 是「关闭先验」的等价写法（全零轨迹）。

## 踩坑指引

两支稳定、中速区结构上为空、刹车是过刹的、先验在带外照样能跟（评测口径错误
造成的假象）—— 见 `experience.md` §19、§20。
