# 视觉评审闭环（主代理 × 监视器子代理）

依据：`experience.md` §23 —— 训练统计会骗人（0% 成功率掩盖了真实的爬楼进展），
画面不会。本 skill 把「看画面」做成一条可复现的流水线。

## 分工（强制）

| 角色 | 做 | 不做 |
| --- | --- | --- |
| 主代理（你） | 改代码/配置、跑训练、渲染视频、派发评审、把结论写进台账 | 不逐帧看图（省上下文） |
| 监视器子代理 | 抽帧、逐帧 Read PNG、按 rubric 产出结构化评审 | 只读；不改代码、不写文档、不跑训练 |

## 流程

### 1. 渲染视频

```bat
.venv\Scripts\python.exe scripts\play.py --run <名字> --mode video [--batch <批次>] [--stage <阶段>]
```

产物：`runs/<run>/videos/<批次>/<阶段>/<阶段>.mp4`（25 fps，480×270，HUD 含指令行）。

### 2. 抽帧（主代理执行）

```bat
.venv\Scripts\python.exe .claude\skills\visual-monitor\read_video.py ^
    runs\<run>\videos\<批次>\<阶段>\<阶段>.mp4 .tmp\review\<run>\<阶段> [--max-frames 16]
```

产物是 `f000.png...` + `manifest.json`（帧清单带 `t_ms`，用来还原时间轴）。
预算规则：**每个视频 ≤16 帧、每帧宽 ≤768**（约 1000 token/帧，单次评审 ≤3 万
token）。多个阶段 = 多个输出目录，一次评审读不完就再派一个子代理。

### 3. 派发监视器（Agent 工具，general-purpose）

Prompt 模板（`{}` 为占位）：

```text
你是机械狗训练结果的视觉评审员。逐帧查看下列 PNG（用 Read 工具），按帧序
还原时间轴（帧时间戳在 {manifest路径}）。

视频来源：{mp4路径}
场景：{台阶高 / 平地；该级指令 vx..vy..wz..，来自课程逐级下发}
共 {N} 帧，均匀采样自全长 {T} 秒。

禁止：修改任何文件；根据代码或训练数字推断结论——你只允许报告画面里
「看到的东西」，每条结论必须引用帧文件名（如 f007.png）作证据。

按以下 rubric 逐项打分（通过 / 可疑 / 失败 + 帧证据）：
1. 躯干姿态：俯仰是否平稳（抬头/低头/低头触地都算异常）；平地阶段尤其
   严格——历史上平地姿态问题曾被成功率数字掩盖。
2. 足端接触：踩实 / 磕梯级边缘 / 打滑 / 悬空试探，发生在哪一帧。
3. 步态：对角小跑是否成形；有没有拖腿、双腿同相、原地踏步。
4. 结局：摔倒 / 卡住 / 超时 / 完成，发生在第几帧、之前的征兆是什么。
5. 指令跟踪：画面位移方向与 HUD 指令行是否一致（HUD 在画面左上角）。

输出格式（严格）：
## 总评
{阶段名}：通过 / 可疑 / 失败 —— 一句话理由
## 逐项
（rubric 五项，各带帧证据）
## 时间线
（异常事件按 t_ms 排列：t=... f0XX.png 发生了什么）
## 假设
（不超过 3 条根因假设，标注置信度；明确说明这是假设不是结论）
```

### 4. 回收与落账（主代理执行）

- **盲评纪律**：prompt 里**不要**写「这版应该修好了 X」——监视器顺着预期
  报喜是这条流水线最大的失效模式。
- 结论进 `train.md` 该 run 的「解读」字段；监视器的「假设」由**主代理**结合
  代码定根因（监视器没读过代码，它的假设常常能对上某个奖励项，也可能全错）。
- 出现新根因 → 按 `agent.md` §1 义务 2 写进 `experience.md`。
- 对照评审（两次训练谁好）：两个视频各派一个子代理、用同一段 rubric，
  主代理只汇总两份结构化结论，不要让单个子代理连读两份帧序列（token 翻倍
  且注意力会被稀释）。

## 已知的坑

- 直接 Read `.mp4` / 动图都看不到内容（Read 对 GIF 只出第一帧，对视频直接
  不支持）——**必须先抽帧**。
- 16 帧均匀采样会漏掉几十毫秒级的瞬时事件（磕边、打滑）。监视器报告可疑
  时间点后，用 `--start/--end` 在该时刻附近加密抽帧再派一轮。
- **渲染分辨率**：`play.py` 默认 `VIDEO_SCALE=2`（mp4 被降到 480×270，
  犬体仅 ~120px、**1px≈3mm**、3cm 台阶只有 9px）⇒「某足是否离地」在物理上
  不可判读，监视器只能写满「无法判定」。**做视觉评审必须
  `--video-scale 1`**（原生 960×540，1px≈1.5mm）。2026-10-15 两名监视器
  都栽在这上面。
- **监视器一律不得在工作区之外写文件**（临时目录也不行）。需要放大观察时
  用 PIL **在内存里**做、不落盘；确需落盘的辅助图一律放
  `.tmp/review/<run>/_scratch/`。2026-10-15 有监视器把 100 张裁剪图写进了
  系统 TEMP（`dog_review_*`），越出了工作区。
- 深夜跑完的长训练：先把视频渲染出来再派评审，评审是只读快操作，不要
  在训练中途占着上下文等结果。
